End-to-end re-derivation of every headline number against on-disk artefacts,

## Bugs found and fixed

### A. `Cm_SC_knox` was not normalised (real bug, fixed)

`pipeline/00_external/06_knox_sc.py` produced `Cm_SC_knox` with range
`[0, 1.325]` while every other cost matrix in `outputs/anndata/full_costs.npz`
sits on `[0, 1]`. Because `MultimodalFGW` adds `sc_weight * Cm_SC` to
`fc_weight * Cm_FC`, the Knox runs were silently weighting SC ~30% more
strongly than the Allen runs — i.e., the previous Knox-vs-Allen comparison
was not apples-to-apples. Fixed by appending
`normalise_cost(d, scheme="max")` to match the Allen pipeline
(`pipeline/03c_build_multimodal_costs.py`).

The negative result holds with the proper normalisation. Re-run via
`pipeline/05e_knox_vs_standard_sc.py` (new script) across all 11 networks
(n=42 LONO folds):

| | Allen | Knox | Δ |
|---|---|---|---|
| Full top-1                  | 2.4%  | 2.4%  | 0 |
| Full top-5                  | 11.9% | 11.9% | 0 |
| Mean rank /2094             | 205.9 | 205.5 | -0.4 |
| `frac_argmax_is_anchor`     | 4.8%  | 4.8%  | 0 |

`docs/comparative_methods.md` updated.

### B. Resolution-improvement claim was apples-to-oranges (fixed)

The "**2.4× resolution improvement** (192 → 469 unique fingerprints)" claim
in `docs/comparative_methods.md` compared the **raw** Allen streamline-density
matrix (192 unique rows in `mouse_sc.npy`) to the **post-processed** Knox
**cost** matrix (469 unique rows in `Cm_SC_knox`). The fair comparison —
cost-vs-cost — is **454 → 469 = 1.03×**, because `log1p +
correlation-distance` collapses much of the apparent advantage of having raw
Knox vectors. Doc updated; the qualitative story (Knox doesn't help anchor
identification) is unchanged.

### C. Subject-CV experiment script was using uniform-coverage subtraction (fixed; numerically negligible)

`src/homer/eval/subject_cv.py` was patched in FIX-5 to use count-aware
held-out-FC subtraction, but the script that actually generates
`outputs/logs/subject_cv.json` lives at
`experiments/D_subject_cv/subject_cv.py` and was still using the old
`(fc_total*N − fc_train*N_train) / N_test` formula (assumes every cell is
covered by every subject, which is false on the human side: ~15% of cells
have `n_obs < 113`). Patched, plus a stale `parents[1]` path bug that broke
the script if run from anywhere other than the homer/ root.

Re-ran with the fix; numerical impact is negligible:

| Config | Metric | OLD | NEW | Δ |
|---|---|---|---|---|
| fc_plus_SC | train_r | 0.3567 | 0.3567 | +0.000000 |
| fc_plus_SC | test_r  | 0.3178 | 0.3178 | +0.000009 |
| fc_only    | train_r | 0.3597 | 0.3597 | +0.000000 |
| fc_only    | test_r  | 0.3189 | 0.3189 | +0.000000 |

Pre-fix copy preserved at `outputs/logs/subject_cv_pre_fix5.json`.

## Things checked and confirmed correct

  converged=True, n_visible_anchors=21.

### FUGW genuinely runs FUGWSolver
Monkey-patching `fugw.solvers.dense.FUGWSolver.solve` confirms it is actually
called when `FUGWModel.fit()` runs. The resulting π has mean row max
concentration **0.078** (vs MultimodalFGW's ~1.0), and the loss breakdown
contains the FUGW-specific keys (`marginal_constraint_dim1/2`,
`gromov_wasserstein`, `regularization`). Not a silent fallback.

### Cost-matrix scales
All 13 cost matrices in `outputs/anndata/full_costs.npz` now lie on [0, 1]
(after the Knox fix above). No scale-mismatch contamination remains.

  genuinely invoked).

  haven't been regenerated.
